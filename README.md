# Sandstorm iOS Driver

A lightweight iOS UI automation stack for **real iPhones and simulators**, built directly on
Apple's XCTest/XCUITest.

**No Appium server. No Node.js. No `appium-xcuitest-driver`. No WebDriver protocol. No WebDriverAgent.**

```
Python SDK / Inspector UI
        |
        v
Mac Controller            (device discovery, build, agent lifecycle, tunnel)
        |
        v
USBMux / TCP tunnel       (loopback on simulators, usbmuxd on devices)
        |
        v
Tiny XCTest/XCUITest Agent on the iPhone   (~1,200 lines of Swift)
        |
        v
Application Under Test
```

## Installation

Requires macOS with Xcode and Python 3.10+.

```bash
git clone https://github.com/Khalilassi/sandstorm-ios-driver.git
cd sandstorm-ios-driver
python3 -m venv .venv && source .venv/bin/activate
python3 -m pip install -e '.[inspector,device]'
sandstorm ios devices          # verify the CLI is on PATH
```

### `zsh: command not found: sandstorm`

The package installed but its console script is not on `PATH`. Either use the
module form, which never depends on `PATH`:

```bash
python3 -m sandstorm_controller ios setup --udid <UDID>
```

or add the script directory to `PATH`. A virtualenv (above) fixes this
automatically; for a `--user` install add the directory pip reports:

```bash
python3 -m site --user-base        # e.g. /Users/you/Library/Python/3.12
export PATH="$(python3 -m site --user-base)/bin:$PATH"   # add to ~/.zshrc
```

Confirm the install location with `python3 -m pip show -f sandstorm-ios`.
Note that `pip install -e .` must be run from the repository root — installing
from a different directory, or with a different interpreter than the one on
your `PATH`, is the usual cause.

## Quick start — simulator

```bash
# 0. Install the Python packages (editable)
python3 -m pip install -e .

# 1. Detect Xcode, build + sign + install the agent (once, not per test run)
sandstorm ios setup --udid <SIMULATOR_UDID>

# 2. Start the long-lived XCTest agent and the tunnel
sandstorm ios start --udid <SIMULATOR_UDID>
#    -> prints host, port and session token

# 3. In another shell: milestone 1
export SANDSTORM_AGENT_PORT=<port> SANDSTORM_TOKEN=<token>
sandstorm ios ping
```

List devices at any time:

```bash
sandstorm ios devices
```

Everything in one process (what `examples/smoke_simulator.py` does):

```bash
PYTHONPATH=ios-sdk:ios-controller python3 examples/smoke_simulator.py <SIMULATOR_UDID>
```

### Watching the run

`simctl` boots simulators **headless** — the runtime is fully live and automatable but draws no
window. The controller therefore also opens Simulator.app and focuses the target device, so you can
watch the automation happen. To keep it invisible (CI):

```bash
export SANDSTORM_HEADLESS=1
```

### Handling iOS interruptions

iOS raises system dialogs ("Save Password?", notification permission) at unpredictable moments and
they silently swallow taps. Let the agent deal with them:

```python
page.set_alert_policy("dismiss", buttons=["Not Now", "Don't Allow", "Cancel"])
```

## Python API

```python
from sandstorm_ios import IOSDevice

device = IOSDevice("DEVICE_UDID")
device.connect()

app = device.app("com.company.app")
app.launch()

page = app.page
page.get_by_id("username").fill("khalil")
page.get_by_id("password").fill("password")
page.get_by_text("Login").tap()

page.get_by_text("Welcome").wait_for(state="visible", timeout=10)
page.screenshot("screen.png")
```

Locator strategies: `accessibilityId`, `identifier`, `label`, `text`, `type`, `predicate`, `index`
— plus compound and chained locators. **XPath is deliberately unsupported.**

```python
page.locator(type="XCUIElementTypeButton", label="Continue").tap()
page.get_by_id("list").locator(label="Row 1").tap()      # chaining
page.swipe(from_=(0.5, 0.8), to=(0.5, 0.2), duration=0.3)  # normalized coords
```

## Signing without an Apple ID

On a managed machine where no Apple ID can be added to Xcode, sign manually
against a profile that is already installed:

```bash
sandstorm ios profiles --udid <UDID>          # what this machine already has
sandstorm ios setup --udid <UDID> \
    --profile "Corp iOS Development" \
    --bundle-prefix com.company               # fit an existing wildcard app ID
```

`--bundle-prefix` renames the agent so the XCTest runner becomes
`com.company.sandstormagent.xctrunner`. See
[docs/PHYSICAL_DEVICE.md](docs/PHYSICAL_DEVICE.md) for the full rules.

## Inspector

```bash
python3 -m pip install -e '.[inspector]'
sandstorm ios inspector --port <port> --token <token>
```

* live screenshot with element highlighting;
* full accessibility hierarchy;
* click the screenshot → the smallest matching visible element is selected in the tree;
* attribute table and ranked locator suggestions with one-click copy;
* interactive Tap / Type / Clear / Long Press / Swipe / Wait For;
* **test recorder** — turn a manual walkthrough into a runnable test.

### Recording a test case

Press **● Record** in the Recorder panel, then drive the app. Every action is
appended as a step and rendered as Python in the *Code* tab:

| Button | Recorded step |
|--------|---------------|
| Launch | `app.launch(relaunch=True)` |
| Tap / Long Press | `page.get_by_id("login_button").tap()` |
| Type / Clear | `page.get_by_id("username").fill("khalil")` |
| Swipe Up | `page.swipe((0.500, 0.750), (0.500, 0.250))` |
| Wait For | `page.get_by_text("Welcome").wait_for(state="visible", timeout=10.0)` |
| Assert Visible / Assert Text | `assert page.get_by_text("Welcome").is_visible()` |
| Screenshot step | `page.screenshot("home.png")` |

Then **Copy code** or **Save as…** to write a file you can run directly:

```bash
sandstorm ios start --udid <UDID> --token <token>
SANDSTORM_TOKEN=<token> pytest test_login_works.py
```

Notes:

* actions are recorded through the **top-ranked locator** shown in the panel,
  and the Inspector executes that same locator — what you replay is what ran;
* coordinates are used only when the tap did not hit a selectable element;
* choose `pytest` (fixture + `test_` function) or `script` (`main()` with
  `try/finally`) in the style box;
* **Fresh** relaunches the app so a replay starts from the recorded state;
* `Undo` drops the last step, and closing the window offers to save.
